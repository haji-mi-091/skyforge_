## 快速开始

**Windows：双击 `SKYFORGE.vbs`**。它会隐藏控制台、启动本地服务器，并用 Chrome/Edge 的 **App 模式 + 全屏（无地址栏、无标签栏、无窗口边框）** 打开游戏。也可以双击 `start.cmd`（会短暂显示控制台）。

- 需要 Node.js；如果机器上没有 Node，脚本会尝试使用 Python 的静态服务器。
- 关闭游戏窗口：`Alt+F4`；暂停菜单里也有“切换全屏”。
- 结束后台服务器：双击 `Stop SKYFORGE.cmd`。
- 如果 App 模式不可用，会退回默认浏览器打开 <http://127.0.0.1:4173/>，可按 `F11` 全屏。

手动启动：

```bash
node server.mjs 4173
# 浏览器打开 http://127.0.0.1:4173/
```

也可以使用：

```bash
python -m http.server 4173 --bind 127.0.0.1
```

> 必须通过本地 HTTP 打开，直接双击 `index.html` 会被浏览器的 ES Module / CORS 策略拦住。运行时不需要联网，也没有构建步骤。

推荐 Chrome / Edge（WebGL2）。显卡性能不足时，在“设置 → 画质”切到“性能”。

## 操作

所有 33 项游戏操作都可在“设置 → 键位修改”重新绑定：点击对应操作的“修改”，按下单键或同时按下组合键，再用鼠标点击“确定”保存。允许多项操作重复使用同一键位；完整组合键优先于其中的单键，无关的飞控与油门仍可同时使用。提供取消、单项默认和恢复全部默认，机炮也可改为键盘触发。设置沿用本机浏览器存档，主菜单、暂停、帮助和 HUD 提示同步更新；下表列出默认键位。鼠标移动和滚轮仍使用原方式。实现及验证说明见 [docs/CONTROLS.md](docs/CONTROLS.md)。

### 鼠标瞄准说明

屏幕中央的**圆圈是鼠标光标**，移动鼠标直接转动相机视角，像 FPS 一样；**十字准星是机头指向**，会从圆心移开并自动追向视角中心。`MouseAim.updateToward()` 把“相机视角方向”作为机头目标：按航向/俯仰误差自动压坡度、协调转弯并拉过载，再由原有电传飞控和 AoA/G 限制执行。视角转动是即时的，机头追随是受物理限制的；相机不再跟随飞机指向，所以回头查看时视角不会被机头拽走。鼠标圆圈与机头十字之间没有任何“皮筋”连线。

满误差会命令约 **8.6G / 83° 坡度**，对应约 **20 秒一圈**的 F-16A 级持续盘旋；滚转轴满杆峰值约 **280°/s**。`W/S` 不经过比例缩放，直接请求 FBW 的可用正/负过载极限，适合做最大性能机动。自由视角（`C`，默认开启）停用机头自动追视角，鼠标仍然控制相机，键盘仍然操纵飞机；再按 `C` 回到鼠标瞄准飞行。瞄准输入和坡度目标都有低通滤波，不会一帧内压满机翼再弹回来；中小幅移动是精确修正，移到边缘则是战斗机级别的压坡度转弯。

`A/D` 不经过鼠标自动驾驶的坡度限制，是直接滚转轴，因此可以完成 360° 滚转和倒飞；按住 `A/D` 时鼠标自动驾驶暂时让出滚转控制，松手后恢复瞄准。`W/S` 是辅助俯仰偏置，地面滑跑仍用直接操纵。

## 三种模式

1. **即时空战**：空中开始，敌机按波次进入，击落得分；阵亡后可以重新出击。
2. **跑道起飞**：从跑道静止开始，预选起飞襟翼。按住左 `Shift` 推油门，约 280 km/h 时按 `S` 抬头（约 330 km/h 离地；不拉杆满加力约 800–850 m、400–450 km/h 自动离地），升空后按 `G` 收起落架。各机型起落架限速不同，超速放轮会损坏。
3. **性能试飞**：高空自由飞行，按 `T` 显示实时气动/发动机遥测，适合测试极速、爬升、过载和滚转。

## 已经实现的内容

- **F-16 数据基线**：F-16A Block 10 气动/动力数据（F100-PW-220、约 105.7 kN 加力推力、27.87 m² 机翼、9G 限制、511 发 M61A1），F-16CM 在此基础上使用 CAD 机身。
- **六自由度刚体气动**：ISA 大气、升力/阻力/侧力、诱导阻力、马赫数阻力上升、失速、地面效应、舵面效率与阻尼、发动机转速滞后、燃油质量变化。
- **电传飞控**：G/滚转角速度指令、AoA/G 限制、作动器速率限制、控制面反解；不是简单的“按键直接转姿态”。
- **战斗机系统**：起落架收放、襟翼、减速板、地面刹车、轮胎摩擦、跑道起飞/接地判定、燃油。玩家机不启用自动过载/超速自损，正常飞行不会自己把发动机或机体“飞坏”；只有战斗损伤、撞地和燃油耗尽会停车。
- **武器与对抗**：红外 / 雷达制导导弹（可被干扰弹、箔条诱骗）、普通与制导炸弹、机炮提前量、命中/爆炸/烟迹、热焰弹、导弹告警。机炮弹链按弹种计算伤害、曳光和穿深，三机都可用 `K` 切换。
- **副油箱**：F-16CM（370 / 300 加仑，合计 3,090 kg 燃油）与歼-10C（1600 / 800 L，合计 3,320 kg）的副油箱燃油取自战雷维基；飞行时先消耗副油箱燃油，机重随之下降，空油箱阻力不变；`O` 抛油箱，重生加满。HUD 续航时间包含副油箱燃油，`T` 遥测显示 `EXT`。歼-10C 油箱尺寸为按容量估算。
- **AI 与任务**：MiG-29 训练目标按 5 架一波刷新，全部击落后进入下一波；**不攻击**、不发射机炮/导弹，只在出生点附近做宽盘旋；在玩家周围 16–32 km 随机位置出现，留给雷达识别和接敌时间。仍然保留地面避让、边界回转和完整飞行模型，可以正常被击落。
- **程序化世界**：60 km × 60 km 岛屿地形、森林、海洋、云层、跑道/滑行道/机库/塔台/油罐、程序化 F-16 与 MiG-29 外形、起落架/襟翼/减速板/加力动画。
- **机体细节**：进气罩与前缘唇口共用同一超椭圆截面，暗色进气道内壁/压气机面；分段收敛喷口、涡轮面与加力环；起落架在地面正确放下、收起时折入机身。
- **座舱**：机身顶部为椭圆开口，配一圈与蒙皮齐平的椭圆边缘。仪表板、模拟表盘、中央 MFD、侧台/油门/脚舵、HUD 框架、简化的杆状飞行员（右手握杆）；`P` 开关高透明有机玻璃座舱盖。
- **航电/态势**：F-16A 风格 **AN/ALR-69** RWR（360°、辐射源识别、搜索/跟踪、无测距；IR 发射不产生 RWR 告警）、默认 **50 km** 量程（`Alt+2` 切换 50/25/10/100 km）/ ±85° TWS B-scope、扫描线、目标高度差/接近率、圆形北向小地图、威胁方位；`M` 打开 **60 km × 60 km 无边框方形战术地图**。
- **HUD**：**无方框、全透明底色**（文字/细线/括号构图）；左侧数据栈按油门、IAS、TAS、Mach、海拔、雷达高度、AAM、热焰弹、箔条、机炮、燃油时间排列；左侧中部 RWR 使用**半透明绿色圆盘和绿色文字**；中下偏左系统状态栏；屏幕中上过载；右上小地图；右中无边框方形 TWS；右下击杀播报。
- **机库与挂载**：主菜单“机库”按钮进入独立机库界面，出战方式在上方、机型在底部一行；“挂载选择 / 收起”开关挂载面板，挂载按类别分段；三机都有涂装选择（F-16CM：基础外观 / Jersey Jerk；歼-16：基础外观 / 银灰迷彩；歼-10C：基础外观 / 八一涂装），在机库切换会实时重涂。挂载预设按机型持久化；F-16CM 默认制空预设为 **4 × AIM-120C + 2 × AIM-9M**。左键拖拽环绕、滚轮缩放；机库地面陈列当前机型可挂的全部武器。导弹、炸弹和制导炸弹都接入战斗系统；可挂载机型登记在 `src/data/hangar.js` 的 `LOADOUT_JETS`。
- **完整前端**：中文菜单、设置持久化、帮助、暂停、阵亡、重开、全屏；菜单卡片、按钮和弹窗去掉方框，只保留文字/下划线/左侧色条。
- **音效**：每个机型有自己的本地音效包（`audio/pack.json`、`audio/j16/pack.json`、`audio/j10c/pack.json`），发动机、加力、座舱和机炮使用从本机 War Thunder 安装解码的样本（来源与哈希见各目录的 `sources.json` 和 `audio/local-sources.json`）；风噪和部分机械声仍是 WebAudio 合成。War Thunder 安装目录不被修改，本项目只提取实际用到的少量样本。
- **性能**：敌机、挂载、尾迹和粒子材质在加载阶段预热；5 架 MiG 与尾迹对象池化，击落时只隐藏/复用而不销毁；每架喷气机的加力光改为纯发光几何，不再动态增减 PointLight，避免雷达发现/击落瞬间触发 Three.js 全场景 shader 重编译。实测首架敌机可见帧从约 430 ms 降到约 4 ms，击落处理约 1–2 ms（软件渲染环境）。

RWR/TWS 的参照能力和简化边界见 [docs/AVIONICS.md](docs/AVIONICS.md)。

按 `M` 打开 60 km × 60 km 方形战术地图。

## 飞行模型标定目标

数据参考公开的 War Thunder Wiki（F-16A Block 10）与公开 F-16/F100 资料，按可玩性和数值稳定性做了工程化近似：

| 项目 | 参考目标 | 本模型 |
| --- | --- | --- |
| 最大速度（约 10,973 m） | 2,156 km/h / 约 M2.03 | 高空加力持续加速可接近 M2.0 |
| 机翼面积 | 27.87 m² | 27.87 m² |
| 军推 | 64.9 kN（F100-PW-220） | 64.9 kN，随马赫/高度衰减 |
| 加力推力 | 105.7 kN（F100-PW-220） | 105.7 kN，随马赫/高度衰减 |
| 发动机重量 | 1,778 kg（F100-PW-220） | 1,778 kg，单独计入总质量 |
| 限制过载 | +9.0 G | +9.0 G（飞控限制并允许瞬时超限损伤） |
| 持续盘旋 | 约 19.5 s（Wiki） | 满鼠标偏转 + 8.6G，约 20 s 一圈；稳定盘旋依赖速度/高度 |
| 滚转速度 | 公开 F-16A 约 270°/s 量级 | 满杆峰值约 280°/s；WT Wiki 的概览表没有单列滚转，按公开 F-16A 数据校准 |
| 起飞滑跑 | 850 m（Wiki） | 起飞襟翼、满加力不拉杆约 849 m / 434 km/h 离地；280 km/h 起拉杆约 331 km/h 离地（见 `docs/TAKEOFF_FLAP_TRIM.md`） |

模型和 War Thunder 的实际飞行模型不是同一套代码，也不追求逐点复刻；目标是让能量、过载、失速和起降手感在工程上自洽。更详细的方程、状态量和验证结果见 [docs/FLIGHT_MODEL.md](docs/FLIGHT_MODEL.md)。

## 测试

本机没有 npm，用 node 直接运行（`package.json` 的 scripts 只是登记表）：

```bash
node tests/flight.test.mjs
```

纯 Node 测试在 `tests/`（飞行、起飞配平、着陆容差、操控、AI、音效，以及各机型的模型和接入测试）。浏览器检查在 `tools/check-*.mjs`，需要先运行 `node server.mjs 4173`。各区域至少要跑哪些测试见 `docs/REPO_CONTRACT.md` §7。

## 参与开发

- 先读 [docs/REPO_CONTRACT.md](docs/REPO_CONTRACT.md)：架构不变量、概念登记表、各目录的写入权限。共享代码不按机型 id 写分支，机型差异写进配置字段或注册表条目。
- 仓库使用 git（默认分支 `main`）。工作区由多个会话共用，所以写操作有分工：只提交自己刚改的路径（按路径 `git add`，不用 `git add -A`），不切分支、不合并、不回滚，推送由主控统一做。并行提交请用 `git worktree`。细节见契约 §4.1。
- 新的配置字段、注册表、目录、存储键或按键属于“新概念”，先按契约 §5 提案，获得维护者同意后再写，并登记进契约。
- 数据要有出处：维基数据放 `sources/wiki/` 的页面快照，用 `tools/import-*-wiki.py` 生成 `src/data/*Wiki.js`；编写的系数在配置注释或 `estimates` 里说明。
- 改动影响到玩家可见的功能、操作或目录时，同步更新本 README；较大的一批工作完成后，在 [docs/changes/](docs/changes/README.md) 记一条改动记录（最近一批：三机统一性修复，含尚待运行的测试清单）。

## 已知限制

- 这是单机技术 Demo，没有多人、存档战役或真实航电。
- 损伤是分区/概率化的简化模型，不模拟液压、起火、舵面卡阻等完整链式故障。
- 红外导引、雷达和电子战是游戏化近似；AI 不使用真实战术数据库。
- RWR 只模拟 ALR-69 的方位/辐射源类型/搜索-跟踪显示，不做真实脉冲重复频率、波段和威胁库全表；红外导弹发射没有 RWR 告警，只保留视觉/游戏提示。
- TWS 不做地面杂波、迎头/尾追截面积、地形遮蔽和电子对抗，当前量程（默认 50 km）内前方 ±85° 的目标按简化探测显示。
- 当前 AI 是**不攻击的训练目标**，不会发射机炮或导弹；箔条数量已进入 HUD/挂载数据，但没有雷达制导威胁可供对抗。本版本不提供“有效但无目标”的假按键。
- War Thunder 的 FMOD bank 是 Gaijin Entertainment 的游戏资产：本项目不修改游戏目录，也不复制整个 bank，只提取实际用到的少量样本并在 `audio/*/sources.json` 记录来源与哈希。本项目是免费、非商业的同人技术 Demo，不提供任何形式的售卖或付费分发。
- 地形/建筑碰撞只有地形高度、跑道和基地边界，不做逐建筑碰撞。
- 不是 Gaijin 官方产品，不包含 War Thunder 的代码。
