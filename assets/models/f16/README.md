# F-16CM Block 52 资产与配置

本目录保存 F-16 CAD 制作资产和正式游戏使用的进气道烘焙资产。2026-10-23 初次补齐资产说明时未运行测试；后续 Jersey Jerk 涂装验证见下文。本次涂装改动没有重建、移动或修改模型。

## 文件用途

| 文件 | 用途 |
| --- | --- |
| `f16_flight.glb` | 正式游戏 `F16CM_BLOCK52.visual.cadModel` 使用的模型；含烘焙后的进气道与机身处理标记 |
| `f16_cad.glb` | 离线制作输入及普通 CAD 预览模型；不是当前游戏加载入口 |
| `f16_cad_high.glb` | 原高精度转换资产，供高精度预览和制作参考，保留 |
| `f16_cad.json` | 制作来源、尺寸、节点与材料等既有审计记录；其中统计对应 CAD 制作资产 |
| `f16-intake-build.json` | `build-f16-intake.mjs` 生成的烘焙报告；当前文件记录 190129 个三角面、86 个网格、3553552 字节，不是本轮重新测量结果 |

`f16_cad.json` 记录的源装配是 `D:\F 16\Body Assy.SLDASM`，组件 STL 输入目录为 `D:\F 16\export`。来源于用户提供的本地 CAD；本说明不作额外授权或实机精度声明。模型单位为米，+Y 向上、−Z 向前，原点采用 CAD 包围盒中心。

## 生成链与运行时

1. SolidWorks 装配导出组件 STL，保留各部件身份。
2. `tools/build-f16-lowpoly.py` 读取组件 STL，分离 `Body_2` 连通实体，保留进气口关键拓扑、舵面和起落架节点。工具默认输出 `f16_cad_low.glb`，若制作目标是 `f16_cad.glb`，需显式指定 `--out`；`--high` 只记录高精度文件路径，不会重建该资产。仓库原有同内容的 low 副本已移入工作区，不能据此删除现用 CAD 输入。
3. `tools/build-f16-intake.mjs` 读取 `f16_cad.glb`，离线拟合进气道、处理前轮舱、清除未引用顶点，写出 `f16_flight.glb` 和 `f16-intake-build.json`。这些工具本轮均未执行。
4. `src/visual/JetModel.js` 经共享 `modelCache.js` 加载游戏配置指定的资产，并装配起落架、座舱、蒙皮、挂架和挂载。异步加载前隐藏外形，避免旧程序化模型闪现；实例资源独立，不修改缓存模板。

CAD 舵面与舱门使用既有铰链矩阵，起落架装配见 [液压起落架说明](../../../docs/HYDRAULIC_GEAR.md)，进气道制作见 [轻量进气道说明](../../../docs/F16_INTAKE_LIGHT.md)，启动缓存见 [飞机加载说明](../../../docs/AIRCRAFT_LOADING.md)。`tools/f16-preview.html` 的普通／高精度 CAD 预览与正式游戏的 `f16_flight.glb` 用途不同。

挂载由 `F16_STATIONS`、`hangar.js` 和 `F16Stores.js` 等现有代码装配，CAD 原有导弹可用于挂载／离架模型。游戏涂装为 `service`（基础外观，默认）和 `jersey-jerk`（Jersey Jerk）；原程序化 F-16 外形已归档到相邻 `f16-procedural/`，不作为加载占位模型。

## 边缘法线修复（2026-10-23）

翼尖及平尾的薄边缘上下表面共用顶点，原 CAD 导入后的面积加权平均使部分顶点法线朝下，产生向翼面内部延伸的暗块。`F16Airframe.js` 的 `rebuildF16SkinNormals` 在 `JetModel._prepareCadRig` 完成全部裁切和装配后重建蒙皮法线：相同坐标的面只在 45° 内共享平滑法线，硬边使用重合但法线不同的顶点。阈值为本次制作选择，保留机身曲面平滑。只在实例装配时处理，不在渲染帧里重算；局部共用几何只处理一次，原几何随后释放。

本次没有改动 GLB 或生成脚本，也没有移动、平滑、缩放、减面或重排三角形；位置、绕序、UV、分组与部件变换保留。新增 `tests/f16-normals.test.mjs` 验证六个实际 CAD 部件与基础几何：88,313 个非退化面的法线均朝向正确，三角形各角坐标和其他属性逐字节一致。完整运行实例另比较收起／闭舱和放下／开舱／舵面偏转两组姿态，各 25 个蒙皮网格，共 171,996 次三角形比较，坐标、顺序、变换矩阵和可见性全部一致，形状偏移 0；七个视角检查翼尖暗块已消除、机身曲面保持平滑。证据在 `work/f16-normals/`，仅供验证，不被运行时引用。

回归：四个 `tests/f16-*.test.mjs`、`check-f16-game`、`check-doors` 均通过；浏览器检查使用原检查逻辑及独立 CDP 进程，避免其他会话共用浏览器。亮度沿用 `measure-skin-brightness.mjs` 的显示／隐藏配对法，仅测 F-16，并在暂停后直接渲染，避免帧等待停滞；`skin-brightness-stats.py` 得到基础外观四个视角近白像素均为 0%。Jersey Jerk 用上述七视角直接检查。

## 尾喷建模与加力开合（2026-10-23）

按用户提供的尾喷参考图，在 `F16Propulsion.js` 中重建 15 片有纵向弧度、搭接边和薄壁厚度的外喷瓣，内衬同步采用独立喷瓣。喷瓣几何只在创建时生成，开合统一使用 `T(hinge)·R·T(−hinge)·base` 刚性变换，不逐帧修改顶点、隐藏或缩放部件。弧度、厚度及开口比例为照片参照的视觉制作值。

常规推力下保持收拢，随 `afterburner` 从 0 到 1 连续展开，撤加力时平滑收回，消除旧转速曲线造成的“全开→收缩→全开”。尾焰沿用原共享着色器及接口，出口半径和轴向位置取实际外喷瓣唇口；其余飞机模型、蒙皮及仿真不变，未重建 GLB。

验证记录见 `work/f16-nozzle/`：专项测试覆盖低转速至军用推力、303 个加力姿态、喷瓣刚性与固定铰链、唇口尺寸和平滑可逆开合；整机预览检查侧面、后方、上方、下方的收拢／展开状态及起落架／座舱盖开闭，浏览器无着色器或运行时错误。五个 `tests/f16-*.test.mjs`、`check-f16-game`、`check-doors` 和 `check-f16-exhaust` 均通过；旧系统测试的常规推力预期、归一化开度步长上限及喷瓣采样索引已同步更新。

## M4：维基事实接入与差异

`src/data/aircraft.js` 已将 `src/data/f16Wiki.js` 的 `F16_WIKI` 接入 `F16CM_BLOCK52.wiki` 和 `performanceTargets`，同时显式登记 `rwrCode`／`rwrType` 为 `F16`、`avionicsSource` 为自身。`control.rollRate` 显式设为原共享默认 `4.9 rad/s`。这些均沿用既有配置字段。

事实来自已保存的 [War Thunder F-16C Block 50 页面](https://wiki.warthunder.com/unit/f_16c_block_50) 快照 `sources/wiki/f16.html`，导入工具为 `tools/import-f16-wiki.py`。源机型是 Block 50，项目名称是 Block 52；它是游戏维基参考，不是实机 Block 52 的性能认证。2026-10-23 导入脚本补读襟翼限速（着陆 463 / 起飞 470 km/h）并重新生成 `f16Wiki.js`；配置现取维基升限 15,240 m、起飞襟翼限速 470 km/h，着陆襟翼仍为继承的 600 km/h。

本轮只接入事实、目标与编写系数说明，不据此修改飞行数值。主要差异如下：

| 项目 | 当前 F-16CM 仿真配置 | 维基快照参考 |
| --- | --- | --- |
| 内油／最大内油 | 2400 kg | 3310 kg |
| 空机质量口径 | 5922 kg 机体＋1778 kg 发动机 | 9150 kg base mass，口径及版本不同 |
| 机炮弹量 | 511 发；初始弹药／供弹机构质量 180 kg | 512 发 |
| 最大 IAS／Mach | 1480 km/h／2.05 | 1555 km/h／2.2 |
| 起落架 IAS | 400 km/h | 482 km/h |
| G 限制 | 飞控指令 +9／−3 G，正向结构阈值 10.8 G | 页面约 +13／−7 G；不能当同口径飞控限制替换 |
| 发动机 | 保留 F100-PW-220，64.9／105.7 kN | 6960／11480 kgf；不是相同版本数据 |
| 性能目标 | 接入参考目标，不代表已经达到 | 2170 km/h @ 10973 m、爬升 300 m/s、转弯 19.5 s、升限 15240 m、起飞滑跑 850 m |

气动曲线、惯量、操纵面速率、发动机响应及耗油、武器动力／阻力／游戏伤害仍是编写系数，在 `estimates` 中明确标注。维基副油箱总燃油 `3090 kg` 不自动写入机内燃油；现有副油箱质量／抛投机制没有分箱供油功能。
